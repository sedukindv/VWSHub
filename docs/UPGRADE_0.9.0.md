# Обновление до Web Video Workspace (WVW) 0.9.0

## До обновления

1. Запишите текущую версию, путь данных, команду запуска, переменные окружения и пользователя службы.
2. Остановите службу/процесс приложения. Для файловой копии все процессы, работающие с этой папкой данных, должны быть остановлены.
3. Сохраните весь прежний код и виртуальное окружение либо версии его зависимостей. Скопируйте **полную папку данных**, включая скрытые `.camkey`, `.flask_secret`, JSON, `images/`, журналы и каталоги защитных копий. Проверьте наличие ключей и доступность копии.
4. Если данные меньше лимита, можно дополнительно скачать ZIP из «Настроек». Это конфигурационный backup; он содержит секреты и используемые изображения, но не является заменой полной копии папки для отката/сохранения журналов.

Веб-backup/restore ограничен 16 МБ в сжатом и суммарном распакованном виде. При превышении сервер отклоняет операцию. Копируйте полную папку данных при остановленной службе: файловая копия не имеет лимита веб-формы. Храните её отдельно от обновляемой установки с ограниченным доступом.

## Обновить код и зависимости

Обновите **весь** проект проверенным архивом релиза или Git, сохранив прежнюю папку данных. Не заменяйте отдельные файлы выборочно. Репозиторий переименован в WVW: [sedukindv/WVW](https://github.com/sedukindv/WVW).

В активном каталоге проекта:

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade -r requirements.txt
ffmpeg -version
ffprobe -version
```

Linux:

```sh
.venv/bin/python -m pip install --upgrade -r requirements.txt
ffmpeg -version
ffprobe -version
```

FFmpeg и FFprobe должны быть в `PATH` пользователя службы, а не только интерактивной консоли. FFprobe необходим для подтверждения звука Live. Без положительной проверки дорожки кнопка звука остаётся недоступной с причиной.

Сохраните существующие `VWSHUB_DATA_DIR`, `WEBVMS_DATA_DIR` (если используется), `FLASK_SECRET_KEY`, `COOKIE_SECURE` и `VWSHUB_RESTART_COMMAND`. Внешнее имя WVW **не требует** переименовывать эти переменные, `vwshub.service`, старые пути установки или форматы `vwshub.devices/spaces/users`. Для новых установок допустима своя папка, но для обновления используйте прежнюю папку данных.

Запускайте обычный `app:app` одним процессом Waitress с несколькими потоками, как в README. Несколько независимых WSGI-процессов не являются поддерживаемым режимом медиапотоков/восстановления.

## Что произойдёт при первом запуске

- Установки старых структур проходят существующую миграцию схемы 3 с защитной копией и транзакцией. ID источников, подключения, ключи и назначения сохраняются. Скачивание архива для пользователей старой модели прав администратор выдаёт заново; уже явные права 0.8.5 не обнуляются.
- Стандартное прежнее имя, равное `VWSHub`, меняется на WVW; своё название администратора сохраняется. Перед изменением создаётся `data/migration-backups/before-wvw-brand-*.zip`.
- Прежние растровые Data URI логотипов/favicon/аватаров проверяются **до** изменения JSON. Создаётся `data/migration-backups/before-images-*.zip`, изображения сохраняются в `data/images/<sha256>.<ext>` (PNG/JPEG/WebP), JSON получает `/images/...`.
- Запись settings/users использует транзакцию. Повторный запуск не мигрирует уже преобразованные значения заново. Некорректное исходное изображение/неизвестная будущая схема вызывает ошибку, а не молчаливый сброс данных. Сохраните исходники и разберите причину перед новым запуском.
- Новые загрузки хранятся на сервере; идентичные файлы используют один SHA-256 путь. Backup включает изображения, на которые ссылаются настройки/пользователи, с проверкой формата и контрольной суммы. SVG по умолчанию/из библиотеки остаётся кодовым ресурсом, а не растровым Data URI в JSON.

Автоматические копии миграции помогают восстановлению, но не заменяют сделанную вами полную копию прежней установки. Они содержат учётные данные и ключи: не публикуйте их и не прикладывайте к публичным Issues.

## Проверка после обновления

1. Откройте приложение и обновите страницу с очисткой кеша (Ctrl+F5). Проверьте WVW 0.9.0, вход администратора и обычного пользователя.
2. Проверьте свои имена/ID устройств и каналов, изображения, пространства/зоны и сохранённые виды. Скрытые камеры должны оставаться закрытыми для Live/архива; существующие подключения не нужно создавать заново.
3. Откройте основные и дополнительные потоки, снимки, архив известной даты, переход через реальный пропуск и скачивание короткого MP4.
4. Откройте «Кастомизацию»: обе палитры/предпросмотры, круглый выбор цветов, сохранение и перезагрузка. «Цвет текста кнопок» задаётся отдельно в каждой теме; «Авто» подбирает чёрный/белый, ручной цвет проверяется на контраст. Предупреждения и кнопки архива должны следовать выбранной теме.
5. Проверьте IANA-пояс сервера, личный пояс и язык. Локализация дат не должна сдвигать локальное время запросов регистратора. Для часов устройства используйте его отдельные настройки.
6. Проверьте аппаратные сведения без записи. «Частично доступно» может быть корректным результатом: сеть не доказывает Live/архив/управление. Непроверенные функции не запускаются автоматически ради зелёного статуса.
7. Для Live Audio выберите камеру/RTSP-профиль, дождитесь подтверждения дорожки и нажмите кнопку. Проверьте остановку при повторном нажатии, переключении камеры и скрытии вкладки. Архивный звук — отдельная возможность.
8. Скачайте новый конфигурационный backup и проверьте его состав. Сохраните копию исходной установки до завершения проверки на ваших устройствах.

## Новые возможности и границы совместимости

MP4 остаётся форматом предпросмотра. Экспорт AVI действительно перекодирует видео в MPEG-4 Part 2 и требует больше CPU; потоковый AVI не содержит окончательного индекса перемотки. Экспорт `.h264/.h265` содержит извлечённый подтверждённый Annex B поток, а не фирменный файл регистратора; временные метки контейнера отсутствуют. H265X не поддерживается. Экспорт всех форматов остаётся **только видео**, без автоматического включения звука.

Аппаратные изменения проверяются повторным чтением. Поддержка зависит от модели/прошивки: не редактируются наугад неизвестные упакованные OSD/маски/координаты и числовой vendor-код часового пояса. NTP/ONVIF и reboot доступны по реальным возможностям и правам устройства. Аппаратный перезапуск требует подтверждения точного имени; принятая команда не означает завершённую загрузку. Серверный restart — отдельная функция с конфигурацией оператора.

Поставляются 28 локалей и английский fallback, RTL для арабского/персидского. Значительная часть переводов подготовлена автоматически и исправлена выборочно; полная редактура носителями всех языков ещё требуется. Актуальный объём и результаты проверок смотрите в отчёте конкретной сборки.

## Веб-восстановление backup

«Настройки» → «Восстановить backup» → ZIP → сводка → `RESTORE`. Проверяются структура, связи, администраторы, форматы, ключи/пароли и изображения; перед заменой создаётся `data/restore-backups/before-restore-*.zip`. Все прежние сеансы завершаются; войдите учётной записью из восстановленной копии. Прерванная транзакция имеет механизм восстановления при следующем запуске.

Для ZIP/набора данных свыше 16 МБ используйте ручное восстановление полной папки при остановленной службе. Восстанавливайте в отдельный пустой каталог с точным содержимым копии, затем укажите его службе. Не объединяйте JSON, изображения и ключи от разных копий.

## Откат на прежнюю версию

1. Остановите WVW и сохраните текущую папку 0.9.0 отдельно для диагностики.
2. Верните **прежний код и его зависимости**.
3. Восстановите **полную папку до обновления**, включая `.camkey`, `.flask_secret` и все изображения. Укажите службе этот отдельный восстановленный каталог и прежние переменные окружения.
4. Запустите прежнюю версию и проверьте вход, подключение и права.

Не запускайте старую версию поверх изменённых JSON 0.9.0: она может не знать серверные ссылки изображений, новые локали/темы/форматы. Защитная копия до image migration может содержать ещё Data URI; это ожидаемое состояние именно для соответствующей старой версии. Никогда не смешивайте её settings/users с новыми ключами другой установки.

## Проверки и тестовые данные

Результаты конкретной сборки находятся в `TEST_REPORT.md` / `BUILD_INFO.json`. README и эта инструкция не объявляют все браузерные или аппаратные тесты пройденными. Физические устройства в среде разработки не подключались; совместимость вашей прошивки, звук и фактическая загрузка после reboot требуют проверки на оборудовании.

`tests/browser/fixture_server.py` запускается только явно, использует `TESTING=True`, отдельные данные и имитацию оборудования/тестовый вход. Рабочий `app.py` его не импортирует: тестовые ответы и автологин в продукте выключены. Не запускайте fixture вместо рабочего приложения. Пользовательские скриншоты, адреса и журналы не входят в публикуемые тестовые материалы.
