# VWSHub 0.7

**Веб-интерфейс видеонаблюдения для XM/XMEye, ONVIF и RTSP.**

VWSHub объединяет живое видео, архив, камеры, группы и управление устройствами. Архив читается напрямую с регистратора — постоянная копия записей на сервере не создаётся.

- Разработчик: **sedukindv**
- Проект: [github.com/sedukindv/VWSHub](https://github.com/sedukindv/VWSHub)
- Предыдущее название: WebVMS

## Возможности

- **Просмотр:** видеостена 1/4/9/16 камер, группы, дерево устройств, перетаскивание камер, снимки и сохранение раскладок.
- **Архив XM/XMEye:** поиск по каналу и времени, шкала записей, перемотка, воспроизведение и экспорт выбранного фрагмента.
- **Камеры:** DVRIP, ONVIF и RTSP; клонирование, группы, автопоиск и ручная проверка доступности.
- **Пользователи:** роли администратора и просмотра, доступ к назначенным группам и отдельное разрешение архива.
- **Устройства:** поддерживаемые команды XM/DVRIP и ONVIF — сведения, сеть, время, кодирование, запись, PTZ, носители и другие доступные функции.
- **Оформление:** логотип, favicon, название, цвет, анимация, темы и русский/английский интерфейс.
- **Сервер:** журнал действий, метрики, резервное копирование и профили нагрузки.

Архив XM воспроизводится по имени файла, возвращённого регистратором. Это важно для прошивок, которые могут игнорировать канал в запросе `ByTime`. Совместимость команд зависит от модели и прошивки; облако XMEye не требуется.

**Внимание:** форматирование HDD удаляет записи всех каналов на этом диске. Форматирование SD-карты удаляет записи с карты.

## Требования

- Python **3.10+** (рекомендуется 3.12).
- FFmpeg в `PATH` процесса VWSHub.
- Сетевой доступ от сервера к камерам и регистраторам.
- Современный браузер. H.264 поддерживается шире; H.265 зависит от браузера и ОС.
- Интернет для первоначальной установки зависимостей.

`requirements.txt` закрепляет версию [OpenIPC/python-dvr](https://github.com/OpenIPC/python-dvr). Пакет `dvrip` из PyPI не является заменой.

## Установка Windows 10/11

Откройте PowerShell и установите Python, Git и FFmpeg:

```powershell
winget install --id Python.Python.3.12 --exact --source winget
winget install --id Git.Git --exact --source winget
winget install --id Gyan.FFmpeg --exact --source winget
```

Перезапустите PowerShell и проверьте:

```powershell
py -3.12 --version
git --version
ffmpeg -version
```

Скачайте проект и установите зависимости:

```powershell
git clone https://github.com/sedukindv/VWSHub.git C:\VWSHub
Set-Location C:\VWSHub
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip setuptools wheel
.\.venv\Scripts\python.exe -m pip install --upgrade -r requirements.txt
```

Запуск только на этом компьютере:

```powershell
.\.venv\Scripts\waitress-serve.exe --listen=127.0.0.1:5000 --threads=24 --channel-timeout=300 app:app
```

Для доступа из локальной сети используйте `--listen=0.0.0.0:5000` и разрешите входящий TCP-порт 5000 в брандмауэре. Не открывайте сервис напрямую в Интернет.

## Установка Debian / Ubuntu

```sh
sudo apt update
sudo apt install --yes git python3 python3-venv python3-pip ffmpeg

mkdir -p "$HOME/apps"
git clone https://github.com/sedukindv/VWSHub.git "$HOME/apps/VWSHub"
cd "$HOME/apps/VWSHub"

python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip setuptools wheel
.venv/bin/python -m pip install --upgrade -r requirements.txt

.venv/bin/waitress-serve --listen=127.0.0.1:5000 --threads=24 --channel-timeout=300 app:app
```

Для первого входа на сервер без рабочего стола создайте SSH-туннель:

```sh
ssh -L 5000:127.0.0.1:5000 USER@SERVER
```

Откройте на своём компьютере [http://127.0.0.1:5000](http://127.0.0.1:5000). Для локальной сети измените адрес Waitress на `0.0.0.0:5000`.

### Автозапуск systemd

Создайте `~/.config/systemd/user/vwshub.service`:

```ini
[Unit]
Description=VWSHub
After=network-online.target

[Service]
Type=simple
WorkingDirectory=%h/apps/VWSHub
ExecStart=%h/apps/VWSHub/.venv/bin/waitress-serve --listen=127.0.0.1:5000 --threads=24 --channel-timeout=300 app:app
Restart=on-failure
RestartSec=5
UMask=0077

[Install]
WantedBy=default.target
```

Включите службу:

```sh
systemctl --user daemon-reload
systemctl --user enable --now vwshub.service
systemctl --user status vwshub.service
journalctl --user -u vwshub.service -n 100
```

Для старта после перезагрузки без входа пользователя включите linger для сервисной учётной записи. Не запускайте VWSHub от root без необходимости.

### HTTPS

Для удалённого доступа используйте VPN или HTTPS reverse proxy. Оставьте Waitress на `127.0.0.1`, отключите буферизацию потоковых ответов и согласуйте таймауты proxy с ожиданием архива. Для HTTPS задайте `COOKIE_SECURE=1`; при обычном HTTP оставьте `0`.

## Первый запуск

1. Откройте VWSHub и создайте первого администратора. Стандартного логина и пароля нет.
2. В разделе «Камеры» добавьте DVRIP-канал или IP-камеру. Укажите учётные данные самого устройства.
3. Для DVRIP интерфейс показывает каналы с 1; протокол использует нумерацию с 0.
4. Для ONVIF укажите адрес и порт устройства, затем выполните проверку подключения.
5. Создайте группы, назначьте камеры и настройте доступ пользователей.
6. Откройте просмотр или архив.

Логин, пароль, адрес, порт и RTSP-путь вводятся в отдельные поля. Не вставляйте URL с паролем в поле адреса.

## Миграция с WebVMS 0.6.x

1. Остановите старую службу и сделайте копию папки данных.
2. Сохраните `users.json`, `groups.json`, `camconfig.json`, **`.camkey`** и **`.flask_secret`**. При использовании прежнего оформления сохраните также `branding.json`.
3. Установите VWSHub в отдельную папку и создайте новое `.venv`.
4. До первого запуска скопируйте старые файлы рядом с `app.py` или укажите старую папку данных через `VWSHUB_DATA_DIR`.
5. Запустите VWSHub. `camconfig.json` будет преобразован в `data/devices.json`.

Старые файлы автоматически не удаляются. Хеши паролей и ключ устройств сохраняются. Без исходного `.camkey` зашифрованные пароли восстановить нельзя — миграция остановится, новый ключ поверх старых данных не создаётся. После переноса проверьте группы и права пользователей.

## Данные и резервное копирование

По умолчанию данные хранятся в `data/` рядом с `app.py`. Путь можно изменить через `VWSHUB_DATA_DIR`.

В разделе «Настройки» администратор может скачать backup. Архив содержит пользователей, группы, устройства, настройки и ключи `.camkey` / `.flask_secret`. **Backup содержит секреты — не публикуйте его и не прикладывайте к GitHub Issues.**

Backup не содержит видео с HDD/SD и временные HLS-фрагменты.

Для восстановления:
1. Остановите VWSHub.
2. Сохраните текущую папку данных.
3. Распакуйте backup во временную папку.
4. Скопируйте содержимое её `data/` в фактически используемую папку данных, включая скрытые ключи.
5. Проверьте права доступа и запустите службу.

Веб-восстановление ZIP не предусмотрено; нужен доступ к файловой системе сервера.

## Производительность

| Профиль | Live | Архив | Буфер архива | Ожидание сети | FFmpeg |
| --- | ---: | ---: | ---: | ---: | ---: |
| Стандартный | 16 | 4 | 16 МБ | 180 с | 2 |
| Максимальный | 64 | 12 | 64 МБ | 300 с | Авто |
| Свой | 1–128 | 1–16 | 2–128 МБ | 30–600 с | 0–32 |

Профили ограничивают ресурсы приложения, но не задают квоты CPU/RAM ОС. Увеличение числа потоков не ускоряет HDD регистратора.

Если архив тормозит:
- Проверьте тот же канал и период в фирменном клиенте и состояние HDD.
- Начните с скорости 1× и одного архивного потока.
- Увеличивайте буфер и таймаут постепенно.
- Проверьте таймауты reverse proxy и поддержку кодека браузером.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `VWSHUB_DATA_DIR` | Внешняя папка данных |
| `WEBVMS_DATA_DIR` | Старое имя переменной папки данных |
| `FLASK_SECRET_KEY` | Секрет сеанса; по умолчанию используется `data/.flask_secret` |
| `COOKIE_SECURE` | `1` для HTTPS, `0` для HTTP |
| `HOST`, `PORT` | Адрес и порт при запуске `python app.py` |
| `VWSHUB_RESTART_COMMAND` | JSON-массив доверенной команды перезапуска |

Переменные задаются окружением процесса. Файл `.env` автоматически не загружается. При запуске Waitress адрес задаётся параметром `--listen`.

Команда перезапуска выполняется без shell и должна быть явно настроена владельцем сервера. Не выдавайте приложению неограниченный `sudo`.

## Настройки интерфейса

Администратор меняет название, логотип, favicon, акцентный цвет и анимацию. Пользователь может выбрать язык, тему, псевдоним и изображение профиля.

Часовой пояс VWSHub, браузера и регистратора настраивается отдельно. Для корректного времени архива синхронизируйте часы устройств.

## Обновление

1. Остановите службу и сохраните backup папки данных с ключами.
2. Обновите код целиком: `git pull` или новая копия проекта.
3. Обновите зависимости внутри виртуального окружения:

Windows:
```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade -r requirements.txt
```

Linux:
```sh
.venv/bin/python -m pip install --upgrade -r requirements.txt
```

4. Запустите службу и проверьте вход, камеры и архив. После обновления интерфейса выполните Ctrl+F5.

Не удаляйте `data/`, `.camkey` и `.flask_secret`. Не используйте глобальный `sudo pip`.

## Тесты

Node.js не нужен для запуска VWSHub. Для тестов установите `requirements-dev.txt`; JS-тесты требуют Node.js 22+.

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest tests -q
node --test tests/archive_core.test.cjs tests/view_model.test.cjs
```

Тесты используют фиктивные данные и не подключаются к реальным камерам. Интеграционные тесты FFmpeg требуют установленный FFmpeg. Последняя проверка версии 0.7: **122 Python-теста и 45 JS-тестов пройдены**, включая 3 теста с FFmpeg на синтетическом архиве.

## Ограничения

- Совместимость зависит от модели и прошивки XM/XMEye/HiWatch. Реальные устройства в релизном тестировании не использовались.
- Доступность функций ONVIF/DVRIP определяется командами и правами конкретного устройства.
- Точность перемотки и MP4 зависит от файлов и ключевых кадров регистратора.
- Пропуски в исходном архиве восстановить нельзя.
- Обратное воспроизведение и передача речи на устройство не поддерживаются.
- Фирменные CMS, Cloud ID и обновление прошивки требуют отдельных интеграций.
- Изменение сети, удаление пользователей и форматирование носителей влияют на само устройство. Перед такими операциями сделайте резервную копию.
