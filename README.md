# VWSHub 0.8

**Веб-VMS для XM/XMEye, ONVIF и RTSP.**

Живое видео, видеостена до 64 окон, архив непосредственно с регистратора, управление устройствами и разграничение доступа. Записи остаются на HDD/SD регистратора — VWSHub не создаёт постоянную копию архива.

- Разработчик: **sedukindv**
- Проект: [github.com/sedukindv/VWSHub](https://github.com/sedukindv/VWSHub)
- Предыдущее название: WebVMS

## Возможности

- **Просмотр:** видеостена до 64 камер, гибкие раскладки, увеличение и перемещение изображения, выбор качества потока и снимки кадров.
- **Архив напрямую с регистратора:** записи воспроизводятся с HDD/SD регистратора без копирования на сервер. Можно быстро найти нужный момент, выбрать фрагмент и скачать его, а также сделать снимок из архива.
- **Подключение камер:** добавление регистраторов и IP-камер по DVRIP, ONVIF и RTSP.
- **Управление оборудованием:** управление камерами и видеорегистраторами прямо из VWSHub.
- **Права пользователей:** разграничение доступа к просмотру камер через группы.
- **Интерфейс и кастомизация:** удобная работа с деревом устройств и видеостеной, кастомизация внешнего вида интерфейса.

## Требования

- Python **3.10+** (рекомендуется 3.12).
- FFmpeg в `PATH` процесса VWSHub.
- Сетевой доступ от сервера к камерам и регистраторам.
- Современный браузер. H.264 поддерживается шире; H.265 зависит от браузера и ОС.
- Интернет для первоначальной установки зависимостей.

`requirements.txt` закрепляет версию [OpenIPC/python-dvr](https://github.com/OpenIPC/python-dvr). Пакет `dvrip` из PyPI не является заменой.

## Установка Windows 10/11

Откройте PowerShell и установите Python, Git и FFmpeg:

```powershell
winget install --id Python.Python.3.12 --exact --source winget
winget install --id Git.Git --exact --source winget
winget install --id Gyan.FFmpeg --exact --source winget
```

Перезапустите PowerShell и проверьте:

```powershell
py -3.12 --version
git --version
ffmpeg -version
```

Скачайте проект и установите зависимости:

```powershell
git clone https://github.com/sedukindv/VWSHub.git C:\VWSHub
Set-Location C:\VWSHub
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip setuptools wheel
.\.venv\Scripts\python.exe -m pip install --upgrade -r requirements.txt
```

Запуск только на этом компьютере:

```powershell
.\.venv\Scripts\waitress-serve.exe --listen=127.0.0.1:5000 --threads=24 --channel-timeout=300 app:app
```

Для доступа из локальной сети используйте `--listen=0.0.0.0:5000` и разрешите входящий TCP-порт 5000 в брандмауэре. Не открывайте сервис напрямую в Интернет.

## Установка Debian / Ubuntu

```sh
sudo apt update
sudo apt install --yes git python3 python3-venv python3-pip ffmpeg

mkdir -p "$HOME/apps"
git clone https://github.com/sedukindv/VWSHub.git "$HOME/apps/VWSHub"
cd "$HOME/apps/VWSHub"

python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip setuptools wheel
.venv/bin/python -m pip install --upgrade -r requirements.txt

.venv/bin/waitress-serve --listen=127.0.0.1:5000 --threads=24 --channel-timeout=300 app:app
```

Для первого входа на сервер без рабочего стола создайте SSH-туннель:

```sh
ssh -L 5000:127.0.0.1:5000 USER@SERVER
```

Откройте на своём компьютере [http://127.0.0.1:5000](http://127.0.0.1:5000). Для локальной сети измените адрес Waitress на `0.0.0.0:5000`.

### Автозапуск systemd

Создайте `~/.config/systemd/user/vwshub.service`:

```ini
[Unit]
Description=VWSHub
After=network-online.target

[Service]
Type=simple
WorkingDirectory=%h/apps/VWSHub
ExecStart=%h/apps/VWSHub/.venv/bin/waitress-serve --listen=127.0.0.1:5000 --threads=24 --channel-timeout=300 app:app
Restart=on-failure
RestartSec=5
UMask=0077

[Install]
WantedBy=default.target
```

Включите службу:

```sh
systemctl --user daemon-reload
systemctl --user enable --now vwshub.service
systemctl --user status vwshub.service
journalctl --user -u vwshub.service -n 100
```

Для старта после перезагрузки без входа пользователя включите linger для сервисной учётной записи. Не запускайте VWSHub от root без необходимости.

### HTTPS

Для удалённого доступа используйте VPN или HTTPS reverse proxy. Оставьте Waitress на `127.0.0.1`, отключите буферизацию потоковых ответов и согласуйте таймауты proxy с ожиданием архива. Для HTTPS задайте `COOKIE_SECURE=1`; при обычном HTTP оставьте `0`.

## Первый запуск

1. Откройте VWSHub и создайте первого администратора. Стандартного логина и пароля нет.
2. В «Камерах» добавьте отдельный канал/IP-камеру либо в «Устройствах» выберите «Добавить регистратор». Укажите учётные данные самого оборудования.
3. Для DVRIP интерфейс показывает каналы с 1; протокол использует нумерацию с 0.
4. Для ONVIF укажите адрес и порт устройства, затем выполните проверку подключения.
5. Создайте группы, назначьте камеры и настройте доступ пользователей.
6. Откройте просмотр или архив.

Логин, пароль, адрес, порт и RTSP-путь вводятся в отдельные поля. Не вставляйте URL с паролем в поле адреса.

## Группы и устройства

Для каждой группы назначаются **Чтение** или **Редактирование**. Редактор может переименовать группу и её камеры, снять камеры с группы. Подключения, удаление камеры из системы, добавление чужих камер и управление оборудованием доступны администратору. Название камеры общее для групп, в которые она входит. Прежние назначения после обновления получают чтение.

Имя регистратора на сайте хранится отдельно от имени его каналов и аппаратного hostname. Оно используется в дереве устройств; способ подписи видеостены выбирается в кастомизации.

Добавление регистратора читает количество/названия каналов DVRIP либо источники и RTSP-профили ONVIF. Существующие подключения не заменяются. Если оборудование не сообщает каналы, операция завершается сообщением об ошибке; вымышленные каналы не создаются.

В «Камерах» импортируются JSON-файлы экспорта VWSHub. По умолчанию добавляются новые подключения; режим обновления по ID выбирается отдельно. Пустой пароль при обновлении сохраняет действующий. В экспорт пароли включаются только по выбранному флажку. Полная копия данных переносится через backup.

Проверка статуса объединяет каналы одного физического устройства. Учитываются работающий поток, ответ порта управления, повторная попытка и RTSP. Открытый TCP-порт подтверждает доступность службы, но не пароль и видеосигнал. Для авторизации и кадра используйте «Проверить подключение».

## Данные и резервное копирование

По умолчанию данные хранятся в `data/` рядом с `app.py`. Путь можно изменить через `VWSHUB_DATA_DIR`.

В разделе «Настройки» администратор может скачать backup. Архив содержит пользователей, группы, устройства, настройки и ключи `.camkey` / `.flask_secret`. **Backup содержит секреты — не публикуйте его и не прикладывайте к GitHub Issues.**

Веб-восстановление: «Настройки» → «Восстановить backup» → выбрать ZIP → проверить сводку → ввести `RESTORE`. Поддерживаются backup 0.7 и 0.8, до 16 МБ в сжатом и распакованном виде. ZIP проверяется без извлечения путей: структура, связи групп, администраторы, форматы и соответствие паролей ключу.

Перед заменой автоматически создаётся `data/restore-backups/before-restore-*.zip`. Замена файлов использует журнал отката; после восстановления нужно войти с учётной записью из backup. Все прежние сеансы завершаются. При сбое записи возвращаются прежние данные; прерванная транзакция восстанавливается при запуске.

Для ручного восстановления остановите VWSHub, сохраните текущую папку, распакуйте backup отдельно и перенесите его `data/` вместе со скрытыми ключами. В 0.8 добавлен `recorders.json`; при восстановлении 0.7 он создаётся автоматически. Проверьте права и запустите службу. Используйте один процесс Waitress с несколькими потоками; несколько процессов WSGI для потокового просмотра и веб-восстановления не поддерживаются.

## Диагностика оборудования

«Логи» → «Оборудование» → «Скачать диагностику». Журнал содержит операции, модель/версию при обнаружении, канал, длительность, число кадров/байт, код завершения FFmpeg и тип ошибки. Пароли, RTSP-адреса с авторизацией, пакеты протокола и видео в экспорт не добавляются. В журнале остаются адреса устройств: перед передачей отчёта проверьте их.

Файлы `data/hardware.jsonl` и три ротации занимают примерно до 8 МБ. Запись включается в настройках; ошибка диска диагностики не прерывает видео. Журналы аудита и оборудования очищаются отдельно, событие очистки остаётся в аудите. Автоматические копии перед восстановлением сохраняются отдельно и не удаляются очисткой логов.

## Производительность

| Профиль | Live | Архив | Буфер архива | Ожидание сети | FFmpeg |
| --- | ---: | ---: | ---: | ---: | ---: |
| Стандартный | 16 | 4 | 16 МБ | 180 с | 2 |
| Максимальный | 64 | 12 | 64 МБ | 300 с | Авто |
| Свой | 1–128 | 1–16 | 2–128 МБ | 30–600 с | 0–32 |

Профили ограничивают ресурсы приложения, но не задают квоты CPU/RAM ОС. Увеличение числа потоков не ускоряет HDD регистратора. Видеостена содержит до 64 окон на странице и до 4096 позиций в виде. Если раскладка превышает лимит live, остальные окна показывают лимит и позволяют открыть камеру отдельно; профиль меняет администратор.

Если архив тормозит:
- Проверьте тот же канал и период в фирменном клиенте и состояние HDD.
- Начните с скорости 1× и одного архивного потока.
- Увеличивайте буфер и таймаут постепенно.
- Проверьте таймауты reverse proxy и поддержку кодека браузером.

## Настройки интерфейса

Администратор меняет название, логотип, favicon, акцентный цвет, анимацию, плотность, углы, подписи регистраторов, часы и отступ видеостены. Пользователь может выбрать язык, тему, псевдоним и изображение профиля.

Часовой пояс VWSHub, браузера и регистратора настраивается отдельно. Для корректного времени архива синхронизируйте часы устройств.

## Обновление

1. Остановите службу и сохраните backup папки данных с ключами.
2. Обновите код целиком: `git pull` или новая копия проекта.
3. Обновите зависимости внутри виртуального окружения:

Windows:
```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade -r requirements.txt
```

Linux:
```sh
.venv/bin/python -m pip install --upgrade -r requirements.txt
```

4. Запустите службу и проверьте вход, камеры и архив. После обновления интерфейса выполните Ctrl+F5. Имена регистраторов создадутся автоматически; текущие пароли и ключи сохранятся. Права редактирования групп назначаются отдельно.

Не удаляйте `data/`, `.camkey` и `.flask_secret`. Не используйте глобальный `sudo pip`.


## Ограничения

- Совместимость зависит от модели и прошивки XM/XMEye/HiWatch.
- Доступность функций ONVIF/DVRIP определяется командами и правами конкретного устройства.
- Точность перемотки и MP4 зависит от файлов и ключевых кадров регистратора.
- Пропуски в исходном архиве восстановить нельзя.
- Обратное воспроизведение и передача речи на устройство не поддерживаются.
- Фирменные CMS, Cloud ID и обновление прошивки требуют отдельных интеграций.
- Изменение сети, удаление пользователей и форматирование носителей влияют на само устройство. Перед такими операциями сделайте резервную копию.

## Проверки

```sh
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
node --test tests/archive_core.test.cjs tests/view_model.test.cjs
```

Для интеграционных тестов нужен настоящий FFmpeg в `PATH` или `FFMPEG_BINARY`. Число пройденных проверок записано в `BUILD_INFO.json`. Реальные регистраторы в среде разработки не подключались: аппаратные сценарии проверяются имитацией ответов, а медиатранспорт — также настоящим FFmpeg на синтетических данных.
