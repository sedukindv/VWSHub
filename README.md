# Web Video Workspace (WVW) 0.9.0

**Веб-VMS для XM/XMEye, ONVIF и RTSP.**

Живое видео, видеостена до 64 окон, архив непосредственно с регистратора, управление устройствами и разграничение доступа. Записи остаются на HDD/SD регистратора — WVW не создаёт постоянную копию архива.

## Возможности

- **Просмотр:** гибкие раскладки до 64 окон, страницы, дерево пространств и устройств, увеличение, перемещение изображения и сохранение видов.
- **Архив напрямую с регистратора:** поиск по пространствам/зонам, слайдер с переходом к записи, последний кадр при загрузке и скачивание выбранного фрагмента.
- **Устройства:** регистраторы и IP-камеры по DVRIP, ONVIF и RTSP; явный выбор каналов без изменения существующих подключений.
- **Пространства и права:** один уровень зон, чтение/редактирование отдельных ресурсов, скрытие источников и раздельное разрешение скачивания.
- **Перенос каталогов:** отдельный импорт/экспорт устройств, пространств и пользователей с предпросмотром и защищённым переносом подключений.
- **Темы:** независимые палитры светлой и тёмной темы, круглые образцы цветов, два предпросмотра, цвет текста акцентных кнопок вручную или «Авто».
- **Локализация:** 28 локальных словарей, английский fallback, локальные числа/даты/множественные формы, RTL для арабского и персидского.
- **Звук Live:** отдельная проверка реальной аудиодорожки выбранного RTSP-профиля и включение по нажатию; звук архива проверяется отдельно.
- **HEVC (H.265):** определение кодека каждого Live-профиля, приоритет проверенного нативного пути и включаемый администратором браузерный декодер для HTTPS. Видео на сервере копируется без перекодирования в H.264.
- **Серверные изображения:** логотипы, favicon и аватары в `data/images`, миграция прежних Data URI и включение изображений в backup.

## Требования

- Python **3.10+** (рекомендуется 3.12).
- FFmpeg в `PATH` процесса WVW; FFprobe нужен для определения кодека Live-профиля и подтверждения его аудиодорожки. На установке только с FFmpeg сохраняется обычная попытка просмотра MPEG-TS без утверждения кодека; автоматический выбор HEVC и подтверждение звука Live требуют FFprobe.
- Сетевой доступ от сервера к камерам и регистраторам.
- Современный браузер. H.264 поддерживается шире; для программного пути HEVC требуются HTTPS и поддерживаемые браузерные API, описанные [ниже](#hevc-h265-в-live).
- Интернет для первоначальной установки зависимостей.

`requirements.txt` закрепляет версию [OpenIPC/python-dvr](https://github.com/OpenIPC/python-dvr). Пакет `dvrip` из PyPI не является заменой.

## Установка Windows 10/11

Откройте PowerShell и установите Python, Git и FFmpeg:

```powershell
winget install --id Python.Python.3.12 --exact --source winget
winget install --id Git.Git --exact --source winget
winget install --id Gyan.FFmpeg --exact --source winget
```

Перезапустите PowerShell и проверьте:

```powershell
py -3.12 --version
git --version
ffmpeg -version
ffprobe -version
```

Скачайте проект и установите зависимости:

```powershell
git clone https://github.com/sedukindv/WVW.git C:\VWSHub
Set-Location C:\VWSHub
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip setuptools wheel
.\.venv\Scripts\python.exe -m pip install --upgrade -r requirements.txt
```

Запуск только на этом компьютере:

```powershell
.\.venv\Scripts\waitress-serve.exe --listen=127.0.0.1:5000 --threads=24 --channel-timeout=300 app:app
```

Для доступа из локальной сети используйте `--listen=0.0.0.0:5000` и разрешите входящий TCP-порт 5000 в брандмауэре. Не открывайте сервис напрямую в Интернет.

## Установка Debian / Ubuntu

```sh
sudo apt update
sudo apt install --yes git python3 python3-venv python3-pip ffmpeg

mkdir -p "$HOME/apps"
git clone https://github.com/sedukindv/WVW.git "$HOME/apps/VWSHub"
cd "$HOME/apps/VWSHub"

python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip setuptools wheel
.venv/bin/python -m pip install --upgrade -r requirements.txt

.venv/bin/waitress-serve --listen=127.0.0.1:5000 --threads=24 --channel-timeout=300 app:app
```

Для первого входа на сервер без рабочего стола создайте SSH-туннель:

```sh
ssh -L 5000:127.0.0.1:5000 USER@SERVER
```

Откройте на своём компьютере [http://127.0.0.1:5000](http://127.0.0.1:5000). Для локальной сети измените адрес Waitress на `0.0.0.0:5000`.

### Автозапуск systemd

Создайте `~/.config/systemd/user/vwshub.service`:

```ini
[Unit]
Description=WVW
After=network-online.target

[Service]
Type=simple
WorkingDirectory=%h/apps/VWSHub
ExecStart=%h/apps/VWSHub/.venv/bin/waitress-serve --listen=127.0.0.1:5000 --threads=24 --channel-timeout=300 app:app
Restart=on-failure
RestartSec=5
UMask=0077

[Install]
WantedBy=default.target
```

Включите службу:

```sh
systemctl --user daemon-reload
systemctl --user enable --now vwshub.service
systemctl --user status vwshub.service
journalctl --user -u vwshub.service -n 100
```

Для старта после перезагрузки без входа пользователя включите linger для сервисной учётной записи. Не запускайте WVW от root без необходимости.

### HTTPS

Для удалённого доступа используйте VPN или HTTPS reverse proxy. Оставьте Waitress на `127.0.0.1`, отключите буферизацию потоковых ответов и согласуйте таймауты proxy с ожиданием архива. Для HTTPS задайте `COOKIE_SECURE=1`; при обычном HTTP оставьте `0`.

Для Debian/Ubuntu предусмотрен отдельный [HTTPS Installer](scripts/https/README.md): локальный CA, сертификат с DNS/IP SAN, настройка сайта Apache/Nginx, продление и пакет доверия Windows. Он запускается администратором отдельно от WVW и требует уже работающую проверяемую systemd-службу. Порт приложения остаётся `127.0.0.1:5000`; установщик не меняет подключения камер, права, данные или флаг HEVC, не переименовывает службу и не заменяет её `ExecStart`. Изменения сайта proxy и служебных переменных, проверки и откат описаны в инструкции компонента.

При работе за этим loopback proxy используются `COOKIE_SECURE=1` и `VWSHUB_TRUST_PROXY=1`; доверие forwarded-заголовкам ограничено одним hop и loopback-источником. При другом размещении сначала согласуйте настройки со своей конфигурацией. Встроенные авторизация, CSRF и проверка Origin сохраняются.

Локальный CA не становится доверенным на Windows автоматически. Его публичный сертификат доставляется отдельно, отпечаток сверяется по доверенному каналу, а Windows helper требует администратора и явного подтверждения `TRUST`. Приложение и серверный installer не импортируют корни в Windows при открытии сайта или включении HEVC. Если у вас уже есть подходящий доверенный HTTPS proxy, заменять его этим компонентом не требуется.

## Первый запуск

1. Откройте WVW и создайте первого администратора. Стандартного логина и пароля нет.
2. В «Устройствах» нажмите «Добавить устройство», выберите регистратор или IP-камеру и укажите параметры подключения. Для регистратора получите список каналов, отметьте нужные и сохраните.
3. Для DVRIP интерфейс показывает каналы с 1; протокол использует нумерацию с 0.
4. Для ONVIF укажите адрес и порт устройства, затем выполните проверку подключения.
5. Создайте пространства и зоны, добавьте камеры и назначьте пользователям чтение или редактирование.
6. Откройте просмотр или архив.

Логин, пароль, адрес, порт и RTSP-путь вводятся в отдельные поля. Не вставляйте URL с паролем в поле адреса.

## Устройства, пространства и права

Физическое устройство хранит общее подключение. Его каналы — отдельные стабильные источники. Удаление последнего канала не удаляет регистратор; повторное чтение каналов добавляет только выбранные новые источники. Обнаруженные каналы не выбираются автоматически. Имена на сайте не меняют аппаратный hostname.

В пространстве камера располагается в корне или одной из зон. Перенос меняет назначение внутри пространства; «Убрать из пространства» сохраняет подключение и остальные пространства. При удалении зоны её камеры возвращаются в корень.

Скрытые камеры остаются в инвентаре и структуре. Просмотр, архив, снимки и прямые медиа-API их не выдают. Сохранённый вид оставляет их ячейки пустыми, сохраняя соседние позиции; последующее включение камеры не восстанавливает старое назначение автоматически.

Чтение даёт доступ к разрешённым источникам; редактирование позволяет менять соответствующий ресурс. Разрешение «Редактирование пространств» включает создание и разрешает изменения существующих пространств/зон только при назначенном им уровне «Редактирование». Выключение сохраняет доступ на чтение. Редактор пространства/зоны может организовывать его камеры и переименовывать доступные источники. Глобальное скрытие, подключение и удаление источника требуют редактирования самого канала или родительского устройства. Право на один канал не разрешает удалять его регистратор или соседние каналы.

Редактор видит «Устройства» и «Пространства». «Управление оборудованием», аппаратные сведения и команды, пользователи и серверные настройки остаются административными. Удаление устройства/канала из WVW не форматирует оборудование и не удаляет его записи. Отзыв прав прекращает соответствующие медиаоперации, сохраняя общий поток других разрешённых пользователей.

Добавление или сопоставление камеры с пространством требует редактирования самой камеры. Это не позволяет повысить чтение камеры через создание своего пространства. Камеры только для чтения можно размещать в личных сохранённых видах просмотра. Новые неразрешённые ссылки при импорте пространств добавляет администратор; редактор может сохранить уже предоставленные ожидающие ссылки.

Подписи IP/имя устройства выбираются в **«Устройства» → «Отображение устройств»**.

## Импорт, экспорт и копирование пользователей

В каждом разделе используется собственный формат JSON версии 1: `vwshub.devices`, `vwshub.spaces` или `vwshub.users`. Обычный экспорт исключает пароли, ключи и сеансы. Защищённый экспорт устройств доступен администратору: Scrypt + Fernet, пароль от 12 символов. Пользовательский экспорт/импорт — только административный.

Перед применением сервер проверяет весь файл и показывает добавления, изменения, пропуски и неразрешённые ссылки. Предпросмотр привязан к пользователю, ревизии данных и сроку действия. Изменившийся каталог требует нового предпросмотра; ошибка записи откатывает всю транзакцию.

Устройства и пространства можно переносить в любом порядке. Отсутствующая камера остаётся ожидающей ссылкой и сопоставляется по происхождению и ID либо вручную. Совпадение локальных ID разных установок не создаёт случайного доступа. Повторный импорт сохраняет подтверждённое сопоставление.

Копия пользователя не получает его пароль или сеанс; копия администратора становится обычным пользователем. Импортированный новый пользователь неактивен до назначения пароля. Не найденные назначения прав остаются ожидающими.

Старые прямые POST `/api/cameras/import`, `/api/groups/import` и добавление всех каналов через `/api/recorders` возвращают HTTP 410. Используйте серверные `/api/transfers/{devices|spaces|users}/preview` и `/apply`, а для добавления каналов — `/api/inventory/probe` и `/api/inventory`. Форматы экспорта 0.8 отличаются от новых; для полного обновления/переноса старой установки используйте её папку данных или backup.

## Данные и резервное копирование

По умолчанию данные хранятся в `data/` рядом с `app.py`. Путь можно изменить через `VWSHUB_DATA_DIR`.

В разделе «Настройки» администратор может скачать backup. Архив содержит пользователей, пространства, зоны, устройства, настройки, используемые изображения из `data/images` и ключи `.camkey` / `.flask_secret`. **Backup содержит секреты — не публикуйте его и не прикладывайте к GitHub Issues.**

Веб-восстановление: «Настройки» → «Восстановить backup» → выбрать ZIP → проверить сводку → ввести `RESTORE`. Поддерживаются совместимые backup 0.7, 0.8, 0.8.5 и 0.9.0, до 16 МБ в сжатом и распакованном виде. При превышении лимита скачивание/веб-восстановление отклоняется; сохраните полную папку данных при остановленной службе и восстанавливайте её вручную. Лимит веб-формы не ограничивает такую файловую копию. ZIP проверяется без извлечения путей: структура, связи пространств/зон, разрешения, администраторы, форматы и соответствие паролей ключу.

Перед заменой автоматически создаётся `data/restore-backups/before-restore-*.zip`. Замена файлов использует журнал отката; после восстановления нужно войти с учётной записью из backup. Все прежние сеансы завершаются. При сбое записи возвращаются прежние данные; прерванная транзакция восстанавливается при запуске.

Для ручного восстановления остановите WVW, сохраните текущую папку, распакуйте backup отдельно и перенесите его `data/` вместе с `images/` и скрытыми ключами. Восстанавливайте в отдельный пустой каталог данных, не накладывая копию поверх другой установки. В 0.8 добавлен `recorders.json`; при восстановлении 0.7 он создаётся автоматически. Проверьте права и запустите службу. Используйте один процесс Waitress с несколькими потоками; несколько процессов WSGI для потокового просмотра и веб-восстановления не поддерживаются.

## Диагностика оборудования

«Логи» → «Оборудование» → «Скачать диагностику». Журнал содержит операции, модель/версию при обнаружении, канал, длительность, число кадров/байт, код завершения FFmpeg и тип ошибки. Пароли, RTSP-адреса с авторизацией, пакеты протокола и видео в экспорт не добавляются. В журнале остаются адреса устройств: перед передачей отчёта проверьте их.

Файлы `data/hardware.jsonl` и три ротации занимают примерно до 8 МБ. Запись включается в настройках; ошибка диска диагностики не прерывает видео. Журналы аудита и оборудования очищаются отдельно, событие очистки остаётся в аудите. Автоматические копии перед восстановлением сохраняются отдельно и не удаляются очисткой логов.

## Производительность

| Профиль | Live | Архив | Буфер архива | Ожидание сети | FFmpeg |
| --- | ---: | ---: | ---: | ---: | ---: |
| Минимальный | 4 | 1 | 8 МБ | 90 с | 1 |
| Стандартный | 16 | 4 | 16 МБ | 180 с | 2 |
| Максимальный | 128 | 16 | 128 МБ | 600 с | 32 |
| Свой | 1–128 | 1–16 | 2–128 МБ | 30–600 с | 0–32 |

Профили ограничивают ресурсы приложения, но не задают квоты CPU/RAM ОС. Ручное изменение лимита выбирает «Свой» и сохраняет остальные значения. Потоки FFmpeg применяются к декодированию/кодированию, но не ускоряют копирование видео без перекодирования. Звук Live имеет отдельный предел до четырёх аудиопроцессов. Увеличение числа потоков не ускоряет HDD регистратора. Видеостена содержит до 64 окон на странице и до 4096 позиций в виде. Если раскладка превышает лимит live, остальные окна показывают лимит и позволяют открыть камеру отдельно; профиль меняет администратор.

Если архив тормозит:
- Проверьте тот же канал и период в фирменном клиенте и состояние HDD.
- Начните с скорости 1× и одного архивного потока.
- Увеличивайте буфер и таймаут постепенно.
- Проверьте таймауты reverse proxy и поддержку кодека браузером.

## Темы, бренд и языки

«Кастомизация» задаёт независимые палитры светлой/тёмной темы: фон, поверхности, основной/вторичный/приглушённый текст, границы, акцент, значки, успех, предупреждение, ошибку и информацию. Основные цвета выделены крупными круглыми образцами, дополнительные раскрываются отдельно. Оба предпросмотра обновляются сразу; рабочий интерфейс получает изменения после «Сохранить».

«Цвет текста кнопок» настраивается отдельно для каждой темы. «Авто» выбирает контрастный чёрный или белый цвет; выбор своего цвета включает ручной режим. Проверка не позволяет сохранить обычный текст с контрастом ниже 4.5:1. Для ручного текста акцентной кнопки проверяется её заливка, а цвет при наведении подстраивается под выбранный текст. Настройки плотности и углов убраны из меню; прежние ключи сохраняются для совместимости.

Стандартный бренд — WVW / Web Video Workspace с PNG-логотипом и favicon пользователя: `static/brand/logo.png` и `static/brand/favicon.png`. Прежние SVG-файлы остаются для совместимости и не являются текущими изображениями по умолчанию. Свой загруженный логотип имеет приоритет над библиотечным значком и стандартным изображением. Логотипы/favicon/аватары хранятся как PNG/JPEG/WebP в `data/images/<sha256>.<ext>`, а JSON содержит `/images/...`. Загружаемый файл SVG не принимается как растровое изображение: SVG-значок выбирается из поставляемой локальной библиотеки.

Локали: `ru`, `en`, `ar`, `be`, `bn`, `cs`, `da`, `nl`, `fa`, `fi`, `fr`, `de`, `hi`, `hu`, `id`, `it`, `ja`, `ko`, `zh-CN`, `nb-NO`, `pl`, `pt-BR`, `es`, `sv`, `zh-TW`, `tr`, `uk`, `vi`. Словари поставляются с приложением; переводчик в Интернете при работе не вызывается. Для отсутствующей строки используется английский fallback; арабский и персидский включают RTL. Переводы подготовлены с автоматическим переводом и дополнительными правками; полная редактура носителями всех языков ещё требуется. Перечень локалей не означает аппаратную сертификацию или лингвистическую проверку каждого перевода.

Пользователь выбирает язык, тему, псевдоним, изображение и свой часовой пояс IANA; пустой пояс наследует серверный. Настройки сервера содержат поиск по полной доступной IANA-базе. Реальные временные отметки интерфейса форматируются в выбранном поясе; запросы архива сохраняют локальное время регистратора без автоматического сдвига. Синхронизируйте часы самого устройства отдельно.

## Оборудование и подтверждение состояния

«Устройства» — каталог подключений и каналов; «Управление оборудованием» — административные операции самого регистратора/камеры. Аппаратные разделы объединяют обзор, систему, время/NTP, сеть/DHCP/DNS, каналы/видео, названия/наложения, хранилище, пользователей и обслуживание. Доступный набор зависит от протокола, прошивки и полномочий учётной записи устройства; неподдерживаемый раздел не выдаётся за рабочий.

Для XM записываются только выбранные известные параметры с сохранением неизвестных полей исходного блока и соседних каналов. Изменения проверяются повторным чтением. ONVIF-сеть сохраняет дополнительные адреса, отправляет только изменённые параметры и тоже требует проверки. «Команда принята» отличается от «Сохранено»: потеря связи или несовпадение readback отображается как неподтверждённый результат.

NTP XM использует возвращённый блок `NetWork.NetNTP`. ONVIF читает `GetNTP`; запись доступна только при положительном подтверждении NTP в возможностях службы, с проверкой адресов и последующим чтением. Режим NTP/ручной использует отдельную стандартную команду с сохранением часового пояса/DST. Универсальные ONVIF-поля порта и интервала не выдумываются. Vendor-код XM TimeZone не превращается в IANA без известной таблицы; упакованные OSD-цвета, маски и координаты не редактируются наугад.

Статусы разделены: сеть, управление, живое видео, архив и звук. Открытый порт подтверждает сеть, но не авторизацию или работоспособность архива. Live/архив подтверждаются по конкретному каналу и актуальным данным; звук — по выбранному профилю. Достижимый, но не полностью проверенный источник показывается как «Частично доступно». Проверка статуса не запускает архив/видеопоток только ради зелёной отметки.

Перезапуск регистратора расположен в его аппаратных действиях, требует администратора, подтверждения и точного имени устройства. Повторная команда блокируется на 60 секунд. ACK означает принятие команды, а завершение загрузки проверяется отдельно. Перезапуск сервера находится в «Настройках» и доступен только при заданном оператором `VWSHUB_RESTART_COMMAND` — JSON-массиве аргументов, без shell.

## HEVC (H.265) в Live

В «Настройках» администратор может включить **«Поддержка HEVC (H.265)»**, подтвердить предупреждение о HTTPS и нагрузке, затем нажать «Применить настройки». Параметр `hevc_support` по умолчанию выключен, сохраняется в `settings.json` и действует для всех пользователей. На прежних установках отсутствие этого ключа означает `false`; остальные настройки сохраняются. Выключение прекращает использование программного HEVC для новых подключений и не требует немедленно обрывать уже работающую камеру.

Кодек определяется по фактическим метаданным конкретного канала и основного/дополнительного RTSP-профиля с ограничением и кешированием проверок. H.264 продолжает использовать MPEG-TS и hls.js без HEVC-плагина. Подтверждённый HEVC передаётся как HLS fMP4 с копированием видео; сервер не перекодирует его в H.264. Сначала проверяются возможности нативного воспроизведения именно этого профиля: точный кодек из SPS/hvcC, MediaCapabilities и создание SourceBuffer. Одного `canPlayType()` недостаточно. Если нативный путь не подтверждён, включённый HEVC-плагин может декодировать HEVC в WASM и кодировать H.264 средствами WebCodecs на компьютере пользователя.

Программный путь требует одновременно `https:` и `window.isSecureContext`, классический MediaSource, WebAssembly, Worker, VideoFrame, EncodedVideoChunk и работающий H.264 VideoEncoder. Обычный HTTP, включая localhost, его не включает; камеры H.264 сохраняют обычный путь. Подтверждённое нативное HEVC может работать и без включения программной поддержки. Браузер без необходимых API получает понятный статус; наличие аппаратного HEVC-декодера не предполагается. Для Firefox нужно отдельно подтвердить доступность H.264 WebCodecs encoder; Safari с одним ManagedMediaSource может использовать нативный HEVC, но не этот программный путь.

Дополнительные кодеки, HEVC Video Extensions, проигрыватели, расширения и Node.js сотрудникам устанавливать не нужно. Закреплённые `@hevcjs/hlsjs-plugin` 0.1.12 и `@hevcjs/core` 1.7.0, Worker, WASM и вспомогательные ресурсы поставляются с сервером в `static/vendor/` и загружаются с того же источника. Клиент не обращается к CDN. Инструкции воспроизводимой сборки, версии зависимостей, лицензии и SHA-256 manifest находятся в [scripts/hevc/README.md](scripts/hevc/README.md); Node.js/npm нужны только при пересборке ресурсов.

Программная обработка ограничена двумя HEVC-плеерами на документ браузера и одним worker на SourceBuffer. Вкладки имеют собственные клиентские ресурсы; общий лимит CPU/RAM всего компьютера этим не задаётся. Действуют и серверные ограничения Live. Закрытие камеры, смена вида, ошибка и отзыв доступа освобождают соответствующие ресурсы и lease. Неизвестный кодек не объявляется H.264/HEVC; фирменный H265X не подменяется обычным HEVC. Только при отсутствии самой утилиты FFprobe разрешается явно обозначенная обычная попытка MPEG-TS без запуска HEVC-плагина и автоматического переподключения. Ошибка или таймаут настоящей проверки не включают эту совместимость.

Программное HEVC-воспроизведение через доверенный HTTPS подтверждено в официальных Chrome и Edge на временном Linux-стенде GitHub Actions (2 теста, включая повторный запуск после освобождения плеера). Windows, Firefox и Safari требуют отдельной проверки. Реальные FFmpeg/FFprobe и синтетические браузерные проверки описаны в отчёте сборки; они не заменяют такую проверку на целевом браузере. Полноценное развёртывание HTTPS Installer в Debian/Ubuntu и импорт доверия Windows также требуют отдельного стендового прогона. Наличие workflow в репозитории не означает успешное выполнение CI.

## Звук и форматы архива

Live Audio включается только после положительного FFprobe-обнаружения аудиодорожки выбранного основного/дополнительного RTSP-профиля и отдельного нажатия кнопки. Звук передаётся отдельным AAC-HLS потоком. Отсутствие FFprobe/FFmpeg, дорожки, права или подтверждения оставляет кнопку недоступной с причиной. Поддержка звука архива не подтверждает звук Live.

Одновременно слушается выбранная камера. Повторное нажатие, переключение камеры/профиля/раздела, скрытие вкладки, выход, потеря прав или ошибка останавливают звук и освобождают его поток. Это воспроизведение звука с камеры, а не передача речи на устройство. Наличие аудиодорожки, RTSP-путь и реальная совместимость требуют проверки на вашей модели.

Предпросмотр архива остаётся MP4. В «Настройках» выбирается формат скачивания:

| Формат | Фактический результат | Ограничения |
| --- | --- | --- |
| MP4 | Фрагментированный MP4, копирование видео без перекодирования | Совместимость зависит от исходного кодека, ключевых кадров и проигрывателя. |
| AVI | RIFF AVI с реальным перекодированием в MPEG-4 Part 2 / YUV420P | Выше нагрузка CPU, возможна потеря качества. Потоковая выдача не содержит окончательного индекса для перемотки; некоторым плеерам требуется переиндексация. |
| Исходный поток | Подтверждённый H.264/HEVC в Annex B, `.h264`/`.h265`, без перекодирования | Это извлечённый видеопоток, а не побайтовая копия фирменного файла. Контейнерных временных меток нет; скорость воспроизведения зависит от данных потока и плеера. Фирменный H265X не поддерживается. |

Экспорт фрагментов во всех трёх форматах содержит только видео. Архивный звук остаётся отдельной функцией просмотра и не добавляется автоматически в экспорт. Неподдержанный исходный кодек и смена кодека внутри выбранного набора не выдаются под ложным расширением.

## Обновление

Пошаговый порядок, миграции и откат: [Обновление до 0.9.0](docs/UPGRADE_0.9.0.md).

Перед обновлением остановите службу и сохраните **всю** папку данных со скрытыми ключами и `images/`, а также прежний код/окружение. Укажите прежний `VWSHUB_DATA_DIR`, обновите проект и зависимости целиком, затем запустите обычный `app:app`. Не создавайте новую пустую установку поверх старой папки.

При первом запуске 0.9.0 старое стандартное имя `VWSHub` заменяется на WVW с копией `data/migration-backups/before-wvw-brand-*.zip`; своё имя сохраняется. Прежние Data URI логотипов/favicon/аватаров проверяются, копируются в серверные файлы и атомарно заменяются ссылками после создания `before-images-*.zip`. Повторный запуск не повторяет уже выполненную миграцию.

Для установки старее 0.8.5 сохраняется миграция структуры в схему 3. ID, подключения и ключи сохраняются, группы становятся пространствами. При этой старой миграции обычным пользователям сохраняется просмотр архива, а скачивание администратор выдаёт заново. Обновление уже действующей 0.8.5/восстановление совместимого backup сохраняет её явные права.

Откат требует остановленной службы, прежнего кода/зависимостей и полной копии **до обновления**. Не запускайте старую версию на JSON 0.9.0, ссылающихся на новые изображения, локали или параметры тем. Не удаляйте `.camkey` и `.flask_secret` и не смешивайте файлы разных установок.

## Ограничения

- Совместимость зависит от модели и прошивки XM/XMEye/HiWatch.
- Доступность функций ONVIF/DVRIP определяется командами и правами конкретного устройства.
- Точность перемотки и MP4 зависит от файлов и ключевых кадров регистратора.
- Пропуски в исходном архиве восстановить нельзя.
- Обратное воспроизведение и передача речи на устройство не поддерживаются.
- Фирменные CMS, Cloud ID и обновление прошивки требуют отдельных интеграций.
- Программный HEVC зависит от HTTPS, WebCodecs и производительности клиента; полная матрица реального Chrome/Edge/Firefox/Safari не заявлена.
- Изменение сети, удаление пользователей и форматирование носителей влияют на само устройство. Перед такими операциями сделайте резервную копию.

## Проверки

```sh
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
node --test --test-isolation=none tests/*.test.cjs
```

Для интеграционных тестов нужен настоящий FFmpeg в `PATH` или `FFMPEG_BINARY`. Фактические результаты конкретной сборки фиксируются в `BUILD_INFO.json` и `TEST_REPORT.md`; наличие команды в README не означает, что все браузерные и аппаратные сценарии пройдены. Реальные регистраторы в среде разработки не подключались: аппаратные сценарии проверяются имитацией ответов, а медиатранспорт — также настоящим FFmpeg на синтетических данных. `tests/browser/fixture_server.py` — только тестовый запуск с имитацией устройств и тестовым автологином; обычный `app.py` его не импортирует и не включает. Не используйте fixture как рабочий сервер и не публикуйте пользовательские скриншоты/журналы в тестовых данных.

Воспроизводимый browser suite и отдельный workflow проверки скриншотов описаны в [tests/browser/README.md](tests/browser/README.md). Обновление эталонов — отдельная явная операция с проверкой человеком; отсутствующие изображения не считаются совпавшими. Тесты HTTPS Installer используют имитации служб и временный каталог; границы реального OpenSSL/Windows-покрытия указаны в [его инструкции](scripts/https/README.md#тесты-и-границы-проверки).

Публичные имя и оформление WVW не переименовывают `VWSHUB_*`, сервисные пути `vwshub-*`, форматы `vwshub.*` или ID существующих данных. Сохраняйте прежний каталог данных, ключи и параметры запуска при обновлении.
